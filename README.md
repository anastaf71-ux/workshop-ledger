# Workshop Ledger V3 — إدارة الدفاتر الفعلية لورشة المحركات

برنامج Windows دون اتصال بالإنترنت (Python, PySide6, SQLite). يتضمن المخزون والمصاريف واليومية وفهرس الزبائن وحساب كل زبون وأوامر شغل المحركات، مع طباعة عربية ودعم تسجيل الخصومات.

## أهم الإضافات

1. **قبض وخصم وتسوية الزبون:** يمكن تسجيل مبلغ مقبوض وخصم في حركة واحدة دون مضاعفة الإيراد أو تسجيل الخصم كقبض نقدي. مثال: حساب 2500، مقبوض 2300، خصم 200، المتبقي صفر. الخصم يُسجل بموجب سبب موثق. الحساب «مكتمل» عندما يكون الرصيد صفرًا.
2. **الخصم على رصيد دفتر قديم:** في نموذج التسوية يوجد خيار «الخصم على رصيد قديم». هذا النوع يخفض الذمم دون تخفيض إيراد أشغال الفترة الحالية؛ الخصم العادي على حسابات الأعمال الجديدة يخفض الإيرادات والأرباح المبسطة.
3. **أمر الشغل:** اسم الزبون، نوع المحرك، عدد السلندرات (1–32، أو 0 عند عدم المعرفة للسجلات السابقة)، السيارة/الآلة، رقم المحرك، الملاحظات، وكل عملية مع العدد وسعر الوحدة والكلفة التقديرية. العمليات المقترحة (تجويف، هون، تجليخ كرنك، قص بوش، تركيب لاينرات وغيرها) قابلة للتعديل.
4. **طباعة عربية RTL:** زر طباعة/معاينة وزر حفظ PDF لكل من كشف حساب الزبون وأمر الشغل. تستخدم أدوات طباعة Qt على جهاز Windows. الطباعة لا تغير قاعدة البيانات.
5. **إدخال الفهرس القديم:** استيراد CSV من ملف `templates/legacy_customers.csv` يضيف الزبائن وأرقام صفحاتهم ورصيدهم الافتتاحي بعد التفريغ **اليدوي**. الأرصدة الافتتاحية لا تدخل في إيرادات الفترة ولا في الصندوق. يمنع الاستيراد المكرر بحسب رقم الصفحة.
6. **UX:** واجهة مرتبة بعلامات تبويب عربية، إجراءات مختصرة من الصفحة الرئيسية، رسائل تسوية واضحة، اختيار العملة USD أو SYP من أعلى النافذة، وعرض قائمة العمليات الشائعة. تدعم العربية والنصوص الإنجليزية المختلطة.

## تنبيه مهم بشأن العملة

يُستخدم مبلغ الحساب نفسه كقيمة رقمية في قاعدة البيانات؛ تغيير الاختيار من USD إلى SYP **يغير تسمية العملة فقط** ولا يجري تحويل أسعار صرف. يجب اختيار عملة واحدة قبل تسجيل أي بيانات حقيقية. توجد قيم افتراضية من النسخ السابقة بعملة USD؛ إذا كان لديك بيانات فعلية بعملة USD فلا تغير الاختيار إلى SYP إلا إذا كنت تريد اعتبار كل الأرقام الحالية مقومة بالليرة السورية. يُخزّن الرقم داخلياً بدقة منزلتين عشريتين في الحالتين.

## كيفية العمل اليومية

1. أضف الزبون من **الزبائن**.
2. سجّل أمر شغل جديد من **أوامر الشغل** وحدّد الزبون والمحرك وعدد السلندرات.
3. أضف العمليات إلى الأمر مع السعر والعدد. **المسودة لا تنشئ ديناً على الزبون**.
4. بعد اعتماد الحساب اضغط **ترحيل الحساب** ليضاف إجمالي الأشغال إلى حساب الزبون مرة واحدة فقط.
5. افتح **حساب الزبون** ثم **قبض / خصم / تسوية**: أدخل المبلغ المقبوض والخصم مع السبب. يظهر المتبقي قبل الحفظ. زر **احتساب الخصم لتصفية الحساب** يساعد على إدخال الفرق. إذا أصبح المتبقي صفرًا يظهر أنه مكتمل.
6. المبلغ المقبوض فقط يظهر في **اليومية** و**حركة الصندوق**، والخصم حركة غير نقدية.
7. لطباعة كشف الحساب أو أمر الشغل، اختر السجل واضغط **طباعة** (معاينة) أو **حفظ PDF**.

## استيراد الدفتر الورقي القديم

انسخ `templates/legacy_customers.csv` إلى هاتفك أو حاسوبك وافتحه بمحرر CSV. الحقول هي:

| column | meaning | sample (fictional) |
|---|---|---|
| `legacy_page` | رقم صفحة الزبون في الدفتر الورقي، قيمة فريدة | `17` |
| `name` | اسم الزبون | `أبو أحمد` |
| `phone` | الهاتف، اختياري | `0999999999` |
| `opening_due` | الرصيد المتبقي عند تاريخ الانتقال إلى البرنامج، بوحدة العملة المختارة، **وليس** مجموع كل الأشغال القديمة | `2500.00` |
| `notes` | رقم الدفتر أو توضيحات، اختياري | `دفتر 2026` |

**لا تضع فواصل آلاف** في المبالغ داخل CSV. مثال `2500.00` وليس `2,500.00`. الملف UTF-8 ويُفضل حفظه UTF-8 BOM لو كتبت أسماء عربية من Windows. يجب أن يكون كل رقم صفحة فريدًا، ويُرفض الملف كله إذا تكرر رقم أو كان مبلغ غير صحيح. لا تختلط الأرصدة المستوردة بالمبيعات الجديدة. لا يحاول التطبيق فهم الصور أو ترحيل المبالغ المكتوبة بخط اليد تلقائيًا، لأنها تحتاج مراجعة يدوية قبل اعتمادها. السجلات التفصيلية لكل أمر شغل قديم تُدخل يدوياً من الواجهة؛ الاستيراد الجماعي يخص الفهرس والأرصدة الافتتاحية فقط في هذه النسخة.

مثال إدخال صف تحت رأس CSV:

```csv
17,أبو أحمد,0999999999,2500.00,دفتر 2026
```

ثم في Windows اختر **الزبائن → استيراد الفهرس القديم CSV**. راجع عدد الزبائن والمجموع الظاهرين في رسالة التأكيد قبل متابعة الاستيراد. لا تستورد سجلات لم يتم تدقيقها. استخدم ملف النسخة الاحتياطية قبل الإدخال الجماعي.

## تحديث مستودع GitHub الحالي من هاتف Android

**أولاً: احفظ نسخة احتياطية من قاعدة بيانات الورشة الحقيقية.** قاعدة البيانات عادة في `%LOCALAPPDATA%\\WorkshopLedger\\workshop.sqlite3`. من البرنامج القديم اضغط **Back up data / نسخة احتياطية** واحفظ نسخة خارج مجلد التطبيق. لا تعد إلى تطبيق أقدم بعد تسجيل خصومات V3.

1. افتح Codespaces في مستودع GitHub الذي استخدمته في نسخ V1 / V2.
2. ارفع الملف `workshop-ledger-v3-update.zip` إلى جذر المستودع.
3. نفذ:

```bash
unzip -o workshop-ledger-v3-update.zip -d .
python -m unittest discover -s tests -v
git add database.py windows.py reports.py README.md tests/test_v3.py templates/legacy_customers.csv
git commit -m "V3 customer discounts, engine cylinders, printing and legacy import"
git push
```

4. افتح **GitHub → Actions → Build Windows EXE**. عند النجاح، افتح آخر run وحمّل `WorkshopLedger-Windows` من **Artifacts**. استخراج ZIP في Windows يعطي `WorkshopLedger.exe`.
5. بعد تركيب النسخة الجديدة، افتح البرنامج وحاول أولاً على نسخة بيانات غير حقيقية، وتحقق من فاتورة وخصم وطباعتها، ثم انتقل للبيانات الحقيقية.

يمكن استخدام `workshop-ledger-v3-full.zip` إذا أردت مشروعاً كاملاً جديداً. الملف `WorkshopLedger_V3_Interactive.html` هو **معاينة في متصفح الهاتف** تحوي بيانات افتراضية؛ لا يشارك قاعدة بيانات Windows ولا يحتفظ بمعاملات الورشة.

## الاختبارات وحدود النسخة

```bash
python -m unittest discover -s tests -v
python app.py --self-test
```

أُنجزت اختبارات قاعدة بيانات Python بنجاح (22 اختبارًا)، واختُبرت المعاينة التفاعلية عبر متصفح Chromium على شاشة موبايل. لم يُشغّل برنامج Qt على Windows فعليّاً في هذه البيئة؛ يقوم GitHub Actions باختبار واجهته وبناء البرنامج على Windows عند رفع الملفات. **لا تعتبر نجاح الاختبارات ضماناً كافياً لاستخدام البرنامج في محاسبة حقيقية دون تجربة عملية ونسخ احتياطي.**

الحدود الحالية: واجهة واحدة/مستخدم واحد، عملة واحدة دون تحويل، بدون ضريبة أو محاسبة مزدوجة، دون حسم تكلفة العمل التقديرية من الربح تلقائياً، ودون تصحيح/عكس مالي متقدم. إذا كانت معاملات قديمة مسجلة فعلياً في نسخة Windows، فاحتفظ بها وتجنب إعادة إدخالها في النسخة الجديدة.
